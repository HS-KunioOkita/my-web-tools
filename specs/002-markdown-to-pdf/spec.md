# Feature Specification: Markdown → PDF 変換ツール

**Feature Branch**: `002-markdown-to-pdf`

**Created**: 2026-05-26

**Status**: Draft

**Input**: User description: "markdown を pdf 化するツールを追加。日本語等マルチバイト文字、mermaid 図に対応。PDF デザインは数パターンから選択可能。PDF 化前のプレビュー画面を用意。業務フロー: Markdown ファイルアップロード or コピー&ペースト → PDF プレビュー画面 → PDF ダウンロードボタンで PDF ダウンロード。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Markdown をペーストしてプレビュー確認の上 PDF をダウンロードする (Priority: P1)

利用者はダッシュボードから「Markdown → PDF」ツールを開き、手元の Markdown テキスト（日本語を含む）をテキスト入力欄にコピー＆ペーストする。即座に右側（あるいは下部）にプレビュー画面が描画され、見出し・段落・表・コードブロックが PDF として出力される見た目で確認できる。利用者は「ダウンロード」ボタンを押すと、プレビューと同じ見た目の PDF ファイルがブラウザ経由でダウンロードされる。

**Why this priority**: 本ツールの中核となる最短の業務フローを 1 本通すこと。ペースト → プレビュー → ダウンロードという一気通貫の体験が成立すれば、ツールとしての価値（手元の Markdown を即座に配布可能な PDF にする）が成立する。ファイルアップロードや mermaid、デザイン切り替えは「あると便利」だが、まずこの最短経路が確実に動くことが MVP として最重要。

**Independent Test**: 日本語を含む 1〜2 ページ程度の Markdown を入力欄にペーストし、プレビュー画面で正しくレンダリングされること、ダウンロードした PDF ファイルを開いて日本語が文字化けせず表示され、レイアウトがプレビューと一致することを確認する。

**Acceptance Scenarios**:

1. **Given** ツール画面を開いた状態, **When** 利用者が日本語を含む Markdown をテキスト入力欄に貼り付ける, **Then** 1 秒以内にプレビュー画面が更新され、見出し・段落・リスト・表・コードブロックが Markdown の意図通りにレンダリングされる
2. **Given** プレビューが表示されている状態, **When** 利用者が「PDF をダウンロード」ボタンを押す, **Then** ブラウザのダウンロードが開始され、PDF ファイル（拡張子 `.pdf`）が保存される
3. **Given** ダウンロードした PDF を開く, **When** 利用者が PDF ビューアでファイルを閲覧する, **Then** 日本語などのマルチバイト文字が文字化けせず正しいフォントで表示され、改行・段落・表のレイアウトがプレビューと視覚的に一致する
4. **Given** 入力欄が空である, **When** 利用者がプレビュー領域を確認する, **Then** 「Markdown を入力するとプレビューがここに表示されます」等の空状態が表示され、ダウンロードボタンは非活性となる

---

### User Story 2 - PDF デザインテンプレートを選んで出力スタイルを切り替える (Priority: P2)

利用者は配布先や用途に合わせて、PDF の見た目（フォント・余白・見出しスタイル・色合い等）を複数用意されたデザインテンプレートから選択できる。テンプレートを切り替えるとプレビュー画面が即座に新しいスタイルで再描画され、ダウンロードされる PDF も選択中のテンプレートに従う。

**Why this priority**: 「数パターン用意して選択」は明示的な要件であり、配布物の見栄えを左右する重要な機能。ただし MVP としては User Story 1 の標準デザイン 1 種類で価値が成立するため、複数テンプレートのうち選択 UI を伴う体験は P2 とする。

**Independent Test**: テンプレート選択 UI（ドロップダウンまたはサムネイル一覧等）から異なるテンプレートを選び、プレビュー画面の見た目が切り替わること、その状態で PDF をダウンロードすると選択中のテンプレートに従った PDF が得られることを確認する。

**Acceptance Scenarios**:

1. **Given** Markdown が入力された状態, **When** 利用者が用意されているテンプレート一覧から別のテンプレートを選択する, **Then** プレビュー画面が選択したテンプレートのスタイル（フォント・余白・見出し装飾・色等）で再描画される
2. **Given** あるテンプレートを選択した状態, **When** 利用者が PDF をダウンロードする, **Then** ダウンロードした PDF の見た目がプレビューと一致し、別のテンプレートのスタイルは含まれない
3. **Given** 初回ツール画面を開いた直後, **When** 利用者がプレビューを確認する, **Then** 既定のテンプレートが自動選択されており、明示的な選択操作なしにプレビューが描画される

---

### User Story 3 - Markdown ファイルをアップロードしてプレビュー確認の上 PDF をダウンロードする (Priority: P2)

利用者は手元の `.md` ファイルをドラッグ&ドロップ、またはファイル選択ダイアログでアップロードする。ファイルの中身が自動的に入力欄に読み込まれ、以降は User Story 1 と同じプレビュー → ダウンロードのフローを辿る。

**Why this priority**: 大きめの Markdown や、既に保存済みのドキュメントを扱う上で実用上必須に近い。ただしペースト経路（P1）でも同じ業務目的は達成可能なため、業務フロー上の代替経路として P2 とする。

**Independent Test**: 日本語と mermaid を含む `.md` ファイルを用意してアップロード操作を行い、入力欄に内容が反映されてプレビューが描画され、その後 PDF をダウンロードできることを確認する。

**Acceptance Scenarios**:

1. **Given** 利用者の手元に `.md` ファイルがある, **When** 利用者がそのファイルをアップロード領域にドラッグ&ドロップする, **Then** ファイルの中身がテキスト入力欄に反映され、プレビューが自動更新される
2. **Given** 拡張子が `.md` または `.markdown` ではないファイルをアップロードしようとする, **When** ファイルが選択される, **Then** 「Markdown ファイルを選択してください」等のエラーメッセージが表示され、入力欄は変化しない
3. **Given** 入力欄に既に Markdown が入力されている状態, **When** 利用者が新たにファイルをアップロードする, **Then** 上書き確認の挙動（確認ダイアログ、もしくは即時上書きで「上書きしました」表示）に従って入力欄の内容が更新される

---

### User Story 4 - mermaid 図を含む Markdown を PDF 化する (Priority: P2)

利用者は ```` ```mermaid ```` で囲んだ mermaid 記法（フローチャート、シーケンス図等）を含む Markdown を入力する。プレビュー画面には mermaid のソースコードではなく、レンダリングされた図として表示され、PDF にも同じ図が画像（ベクター/ラスター）として埋め込まれる。

**Why this priority**: 「mermaid 図も正しく PDF 化」は明示要件であり、技術文書を扱う上で価値が高い。一方、mermaid を含まないドキュメントでも本ツールは十分に役立つため、コア体験（P1）には乗せず P2 として独立検証可能な機能とする。

**Independent Test**: フローチャートおよびシーケンス図を含む Markdown を入力し、プレビューに図として描画されること、ダウンロードした PDF を開いて図が欠落・ソースコード表示・崩れなしに表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ```` ```mermaid ```` ブロックで記述した flowchart を含む Markdown が入力されている, **When** 利用者がプレビュー画面を見る, **Then** mermaid ソースコードは隠れ、対応するフローチャート図が描画される
2. **Given** mermaid を含む Markdown のプレビューが表示されている, **When** 利用者が PDF をダウンロードする, **Then** PDF 内に mermaid 図が画像として埋め込まれており、図のラベル文字（日本語含む）も判読可能な状態で表示される
3. **Given** mermaid 構文に誤りがある Markdown が入力されている, **When** 利用者がプレビュー画面を見る, **Then** プレビュー上の該当箇所にエラーメッセージ（または「mermaid 構文エラー」を示す代替表示）が示され、その他の Markdown 部分のプレビュー・PDF 化はブロックされない

---

### Edge Cases

- 入力欄に非常に大きな Markdown（数百ページ相当）が貼り付けられた場合、プレビュー描画が極端に遅延しないこと（後述の SC-001 に従う）、または明示的な上限超過メッセージを返すこと
- Markdown 内に画像（`![alt](URL)`）が含まれる場合の挙動
  - HTTPS の外部 URL: PDF 内に画像として埋め込む
  - データ URI: PDF 内に画像として埋め込む
  - ローカル相対パス: PDF にはプレースホルダ（または「画像を読み込めません」表示）として出力（ローカルパス解決は今回スコープ外）
- ネットワーク遮断下で外部画像 URL を読み込めない場合、プレビュー・PDF ともに該当画像位置に代替表示を出し、PDF 生成自体は失敗しない
- 全角スペース・絵文字・縦書き対象外の文字種が含まれていても文字化けしない
- 改ページ目的の特殊記法（HTML `<div style="page-break-after: always">` 等）が含まれていた場合の挙動は本フィーチャーでは未対応とし、通常の Markdown レンダリング結果としてのみ扱う
- PDF ダウンロード時のファイル名は、アップロード時はその `.md` ファイル名の拡張子を `.pdf` に置換、ペースト時は既定名（例: `document.pdf`）とする
- 同じ Markdown でもテンプレート選択を切り替えた直後にダウンロードした PDF は、切り替え後のテンプレートが反映されている（プレビューとダウンロードの間でテンプレート選択が記憶されている）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 利用者は Markdown のテキストを、ツール画面上のテキスト入力欄に直接ペースト（または手入力）できなければならない
- **FR-002**: 利用者は `.md` または `.markdown` 拡張子のファイルを、ドラッグ&ドロップまたはファイル選択ダイアログ経由でアップロードでき、その中身がテキスト入力欄に反映されなければならない
- **FR-003**: システムは入力された Markdown を、ペースト/アップロードからおおむね即時（SC-001 に従う）にプレビュー画面へレンダリングしなければならない
- **FR-004**: プレビュー画面は、ダウンロードされる PDF と視覚的に一致する（フォント・余白・見出しスタイル・配色・図の見え方）必要がある
- **FR-005**: システムは日本語等のマルチバイト文字を、プレビューおよび PDF の両方で文字化けせず正しく表示できなければならない
- **FR-006**: システムは ```` ```mermaid ```` で囲んだ mermaid 記法（少なくとも flowchart、sequenceDiagram、classDiagram）を、プレビューおよび PDF において図として描画しなければならない
- **FR-007**: システムは複数の PDF デザインテンプレート（最低 3 種類: 標準・ビジネス文書・技術文書）を提供し、利用者は明示的な UI 操作によりテンプレートを切り替えられなければならない
- **FR-008**: テンプレートを切り替えた場合、プレビュー画面およびその後生成される PDF の見た目は即時に新テンプレートへ追従しなければならない
- **FR-009**: 利用者が「PDF をダウンロード」ボタンを押した際、システムは現在のプレビューと一致する内容の PDF ファイルをブラウザのダウンロードとして提供しなければならない
- **FR-010**: 入力欄が空、あるいは Markdown としてレンダリング可能な内容が含まれていない場合、ダウンロードボタンは非活性となり、利用者は誤って空 PDF を生成できないようにしなければならない
- **FR-011**: mermaid 構文エラーや、外部画像の読み込み失敗等の局所的なエラーが発生した場合でも、PDF 生成全体が失敗するのではなく、該当箇所をプレースホルダ/エラー表示として出力し、その他の正常箇所はそのまま PDF に含めなければならない
- **FR-012**: アップロードされたファイル、ペーストされた Markdown 本文、生成された PDF を含む、ユーザーが投入した文書内容はサーバー側に永続化してはならない（リクエスト処理の範囲を超えて保存しない）
- **FR-013**: 本ツールは [001-tools-dashboard](../001-tools-dashboard/spec.md) で定義されたツールカタログにエントリを持ち、ダッシュボード経由で遷移できなければならない

### Key Entities

- **Markdown ドキュメント**: 利用者が入力したテキスト本体。プレーンな Markdown 文字列で、mermaid コードブロック・画像参照・表・コードブロック・見出し等を含み得る。永続化対象ではない。
- **PDF デザインテンプレート**: PDF とプレビューの見た目を決める設定群。属性として「テンプレート ID」「表示名」「想定用途の短い説明」を持ち、内部にはフォント・余白・見出し装飾・図のスタイル等の見た目決定情報を含む。最低 3 種類が定義済みで、利用者は実行時に 1 つを選択する。
- **プレビュー**: 入力中の Markdown を、現在選択中のデザインテンプレートで描画した、PDF と同じ見た目のレンダリング結果。状態はクライアント側のみに存在し、画面遷移やリロードで失われてよい。
- **生成 PDF**: ダウンロードボタン押下の結果として生成されるバイナリ。`.pdf` 拡張子を持ち、入力 Markdown とテンプレートの組み合わせから決定される。サーバー側に保存はしない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 日本語を含む 5 ページ以下の Markdown を貼り付けてからプレビューが完全に描画されるまでの時間が、初回・以降ともに 95% のケースで 2 秒以内である
- **SC-002**: 5 ページ以下の Markdown について、ダウンロードボタン押下から PDF ダウンロード開始までの時間が 95% のケースで 5 秒以内である
- **SC-003**: 日本語・英数字・記号・絵文字を含むサンプル Markdown について、生成された PDF 上で文字化け（豆腐表示、置換文字、欠落）が 1 文字も発生しない
- **SC-004**: mermaid（flowchart, sequenceDiagram, classDiagram の 3 種）を含むサンプル Markdown について、PDF 内で図が欠落・ソースコード表示・図形崩れなしに描画される（3 種それぞれで合格すること）
- **SC-005**: 提供されたすべての PDF デザインテンプレートにおいて、テンプレート切り替え後に生成された PDF のスタイルがプレビューと一致する（フォント、余白、見出し装飾、配色の主要 4 項目すべてで視覚的差異がないこと）
- **SC-006**: ツール画面を初めて開いた利用者が、サンプル Markdown を貼り付けて PDF をダウンロードするまでを、ヘルプ・ドキュメントを参照せずに 1 分以内に完了できる（初見ユーザビリティテスト 5 名中 4 名以上）
- **SC-007**: 利用者の Markdown 本文・アップロードファイル・生成 PDF が、リクエスト処理完了後にサーバー側ストレージ（ファイルシステム、DB、ログを含む）に残存しない（運用検査で残存が確認されないこと）

## Assumptions

- 本ツールは [001-tools-dashboard](../001-tools-dashboard/spec.md) で構築されたローカル Web ツール基盤の上に、新規ツールとして追加される。ダッシュボードのカタログにエントリを 1 件追加することで一覧表示・遷移導線は確保される。
- 利用者は基本的に開発者・社内ドキュメント作成者を想定し、Markdown 記法・mermaid 記法の基礎知識を持つ。初心者向けの Markdown 入門ガイド機能は本フィーチャーのスコープ外。
- PDF の用紙サイズは A4 縦を既定とする。サイズ切り替え（A3、Letter、横向き等）は本フィーチャーのスコープ外で、将来要件として保留する。
- Markdown 内の画像のうち、HTTPS の外部 URL と data URI は PDF 埋め込み対象。ローカル相対パス画像（`./images/foo.png` 等）はサーバー上のファイルとして解決しないため、PDF 上は代替表示となる。
- 1 回のリクエストで処理する Markdown は、本文 1MB / 50,000 文字以下を想定する。これを超過した場合の挙動（拒否か、警告付き処理続行か）は実装側の合理的なデフォルトに委ねる。
- 本ツールは [001-tools-dashboard](../001-tools-dashboard/spec.md) が前提とするローカル稼働環境上で動作し、外部ネットワークが届かない場合でも、外部 URL 画像の取得失敗を除き機能の大部分が成立する必要がある。
- デザインテンプレートの数は最低 3 種類（標準・ビジネス文書・技術文書）。4 種類以上への増加は将来要件で、初期リリースでは 3 種類の品質保証を優先する。
- mermaid のサポート対象は本仕様時点で flowchart / sequenceDiagram / classDiagram の 3 種を最低保証範囲とし、gantt・pie・stateDiagram 等のその他図種が描画できるかは「ベストエフォート（できれば描画する）」扱いとする。
- 入力 Markdown 本文と生成 PDF はサーバー側に永続化しない。プレビュー・PDF 生成のためにメモリ上で一時的に保持する範囲は許容する。
