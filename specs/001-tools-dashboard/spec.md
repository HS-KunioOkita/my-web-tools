# Feature Specification: ローカルWebツール群ダッシュボード基盤

**Feature Branch**: `001-tools-dashboard`

**Created**: 2026-05-26

**Status**: Draft

**Input**: User description: "ローカルPC上で動作させるWebツール群の基盤を作りたい。ダッシュボードでツール一覧を表示。技術スタック: Next.js, PostgreSQL (docker-compose), SSR。後続予定のツール: markdown→PDF(日本語+mermaid)、時刻変換(Unixtime⇄ISO等)、JSONフォーマッター。今回はツール本体の実装は不要。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ダッシュボードでツール一覧を確認する (Priority: P1)

利用者は自分のローカルPCでWebツール群のサービスを起動し、ブラウザでダッシュボードのトップページを開く。そこには登録済みツールの一覧が一覧表示され、各ツールの名称・概要・カテゴリ（任意）が一目で分かる。利用者は一覧から目当てのツールを見つけ出せる。

**Why this priority**: 本フィーチャーの中核は「複数の小さなツールへの入口を一箇所にまとめる」こと。ダッシュボードでツール一覧が見えれば、たとえ個別ツールがまだ未実装でも「基盤としての価値」が成立し、後続のツール追加を待つ最小単位の出口になる。

**Independent Test**: ダッシュボードURLへアクセスし、登録されたツールの一覧が画面に描画されることを確認する。ツールが0件の場合は「ツール未登録」を示す空状態が表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** ツールカタログに3件のツールが登録された状態, **When** 利用者がダッシュボードを開く, **Then** 3件のツール名・概要が一覧表示される
2. **Given** ツールカタログに1件もツールが登録されていない状態, **When** 利用者がダッシュボードを開く, **Then** 「現在利用可能なツールはありません」等の空状態が表示される
3. **Given** ダッシュボードが正常に起動している, **When** 初回アクセスする, **Then** ページの初期描画時点で既にツール一覧が含まれている（描画後にJSで取得して差し込む形ではない）

---

### User Story 2 - 一覧から各ツールへ遷移する (Priority: P2)

ダッシュボードで一覧表示されている各ツールはクリック可能なリンクとなっており、利用者はそこから個別ツールのページへ遷移できる。個別ツール本体は本フィーチャーのスコープ外だが、各エントリは「遷移先URLを保持し、リンクとして機能する」必要がある。

**Why this priority**: 一覧表示だけでは“見える”だけで“使えない”。最低限の遷移導線があってはじめて、後から追加するツールが価値を発揮できる。ただしツール本体は今回作らないため、遷移先がプレースホルダ（"Coming soon"）でも成立するので P2。

**Independent Test**: ダッシュボードで任意のツールエントリをクリックし、対応する個別ツールページ（または未実装プレースホルダ）に遷移することを確認する。

**Acceptance Scenarios**:

1. **Given** ダッシュボードに「JSONフォーマッター」のエントリが表示されている, **When** 利用者がそのエントリをクリックする, **Then** 対応する個別ページへ遷移する
2. **Given** 遷移先ツールが未実装である, **When** 利用者がそのエントリをクリックする, **Then** 未実装である旨を示すプレースホルダページが表示される（500/404にはならない）

---

### User Story 3 - 新規ツールをカタログに追加できる (Priority: P3)

開発者は新しいツールを実装した際、ツールカタログに自分のツールのメタ情報（名称・概要・遷移先パス等）を登録することで、追加コードや再ビルド以外の特別な手順なしにダッシュボードに自動的に表示できる。

**Why this priority**: 拡張性は本基盤の存在意義の根幹。ただし「今は追加不要」と明示されており、初期リリース時点では実機能としては未行使。「将来のツール追加が容易である」ことを基盤側で担保しておくため、設計に明確に含めるが優先度はP3。

**Independent Test**: 既存ツール定義に倣って1件のサンプルツールを追加し、ダッシュボードを再描画すると新しいツールが一覧に出現することを確認する。

**Acceptance Scenarios**:

1. **Given** 開発者が新しいツール定義を追加した状態でアプリを再起動する, **When** ダッシュボードを開く, **Then** 新規ツールが一覧に追加されている
2. **Given** ツール定義に必須項目（名称・遷移先パス）の欠落がある, **When** アプリ起動またはダッシュボード描画を行う, **Then** 不正な定義は除外され、ダッシュボード全体は壊れず表示される

---

### Edge Cases

- ツール定義が0件: 「現在利用可能なツールはありません」の空状態を表示し、エラーにはしない
- ツール定義に重複（同名・同パス）がある場合: 重複を一度だけ表示し、警告ログを残す
- データ永続化層（PostgreSQL）が起動していない/接続できない: ダッシュボード自体は最低限「接続できません」のメッセージを表示して落ちない（個別ツールのDB依存有無は将来仕様）
- ブラウザで個別ツール未実装パスをブックマーク等から直接開いた場合: 未実装プレースホルダで適切に応答する（500にならない）
- カタログに多数（例: 50件以上）のツールが追加された場合: スクロール可能で、表示崩れが起きない

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: システムはダッシュボードのトップページで、登録済みツールの一覧を表示できなければならない
- **FR-002**: 一覧の各ツール要素は、少なくとも「ツール名」と「概要（短い説明文）」を含まなければならない
- **FR-003**: 一覧の各ツール要素は、対応する個別ツールページへの遷移リンクを持たなければならない
- **FR-004**: ツール一覧はサーバ側で構築・描画され、初回HTMLレスポンスの時点で利用者に閲覧可能な状態で届かなければならない
- **FR-005**: 登録ツールが0件の場合、システムはエラーではなく「利用可能なツールがない」旨を示す空状態を表示しなければならない
- **FR-006**: 新規ツールをカタログに追加した場合、ダッシュボードはサービス再起動後（または再描画後）に追加分を反映できなければならない
- **FR-007**: システムはローカルPC（単一ユーザ環境）での利用を前提とし、認証・マルチユーザ機能を提供しない
- **FR-008**: システムはローカル開発環境を一括起動できる手段を提供し、利用者はアプリ本体とデータ永続化層を1コマンド相当の手順で起動できなければならない
- **FR-009**: データ永続化層（DB）がダウンしている場合でも、ダッシュボードのトップページは最低限の表示を維持し、原因が分かるメッセージを返さなければならない
- **FR-010**: ツールカタログのエントリは、リポジトリ管理下のコード/設定ファイルとして宣言する方式で管理しなければならない（運用時にDB上で動的に追加・編集する管理方式は採用しない）。各ツールの追加・変更はGitの変更管理（コードレビュー含む）の対象となり、サービス再起動で反映される

### Key Entities *(include if feature involves data)*

- **Tool (ツール)**: ダッシュボードに掲載される個別ツールの一エントリ。主属性: 識別子、表示名、概要、遷移先パス、（任意で）カテゴリ・表示順
- **Tool Catalog (ツールカタログ)**: 全ツールの集合。ダッシュボードに表示される順序・カテゴリ分けの根拠となる

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 利用者はダッシュボードURLを開いてから2秒以内に、ツール一覧が画面に表示された状態を視認できる（ローカル環境での初回サーバ描画を含む）
- **SC-002**: 開発者は新しいツール1件をカタログに登録するために、メタ情報の宣言とサービス再起動以外の追加作業を必要としない（手順数で5ステップ以下）
- **SC-003**: 利用者はサービス起動コマンドを1回実行するだけで、ダッシュボードとデータ永続化層を含む開発環境を立ち上げられる
- **SC-004**: ダッシュボード上で登録ツールが0件の状態、1件の状態、20件以上の状態のいずれにおいても、画面崩れ・エラー・空白ページなどの異常がなく一貫した表示が得られる

## Assumptions

- 本フィーチャーはローカルPC単一利用者向けの基盤であり、外部公開・マルチテナント・認証は要件外とする
- 「ツール本体（markdown→PDF、時刻変換、JSONフォーマッター 等）」は本フィーチャーのスコープ外。今回はあくまでダッシュボード基盤と、後続ツールを受け入れる枠組みのみを構築する
- データ永続化層は今回ツールカタログ表示用には必須ではないが、後続ツールが利用するため基盤として同梱起動できる状態にしておく
- ダッシュボードURLはローカルホストの既定ポートで起動した直後にブラウザから直接開かれる前提（ランディング/オンボーディングは不要）
- 個別ツールページの設計（URL構造、レイアウト等）は本フィーチャーでは「遷移できる」レベルまでに留め、各ツール実装フィーチャーで個別に定義する
- 表示言語は日本語UIを基本とする（利用者・開発者ともに日本語話者を前提）
- ツールカタログのメタ情報はリポジトリ内のコード/設定ファイルとして宣言する（FR-010）。データ永続化層は後続ツール本体のデータ用途に充て、カタログ自体は運用時にDBで動的編集しない
